**Scope:** Public pesticide-treatment notices relevant to beekeepers in Smolensk Oblast.  
**Requirement:** [SRC-R01 and SRC-R02](specs/active/subspecs/source-ingestion.md).

This register records inspectable publications, not a machine-ingestion authorization or a live source catalog. The links below were inspected through publicly indexed page/PDF views. The website operators' automated-access terms, `robots.txt` directives, rate limits, and redistribution rights have **not** been verified by an authorized operator. In particular, an indexable page is not evidence of permission to crawl, download attachments in bulk, or reproduce its contents.

## Operator follow-up before enabling a source

1. Verify the publisher's identity and current official domain independently; record a dated page or response supporting authorized collection and downstream display. Where terms are unclear, seek written permission or a clearly applicable published license.
2. Check `robots.txt`, any `Terms of Use` or copyright notice, the allowed URL scope, attachment ownership, pagination, acceptable rate/cadence and whether the notice may be retained and redistributed. Record the reviewer's name and UTC time.
3. Test one permitted document manually from an authorized environment: HTTP status, redirect chain, content type, maximum size, dates, encoding and stable canonical URL. Document failures without expanding allowlists automatically.
4. Establish a least-privilege, authenticated operator workflow for registration and revocation. Review credentials and audit trails must not be exposed by public source endpoints.
5. Only then set a narrow host/path policy and disabled-by-default fetch configuration, verify the restriction tests and obtain explicit approval for the first scheduled request.

## Policy and science cautions

- The reference grant proposal includes a three-day notice assumption. A [2026-03-27 Rosselkhoznadzor communication](https://www.garant.ru/products/ipo/prime/doc/413900975/) reports that the amended Article 16 of Federal Law No. 490-FZ (effective 2026-03-01) generally specifies notification **between ten and five calendar days before application**, with an emergency exception. Verify the current official legislation independently before implementing legal compliance labels; do not infer lawfulness from the date fields of a notice.
- The names of pesticides and hazard classes in source notices are **publisher claims**, not independently validated toxicity or safety assessments. Missing notices do not prove absence of agricultural treatment.
- The source project suggests a Saturn-related API and region identifier. Neither its undocumented endpoint nor its automated-access rights were verified in this research. Do not add it to approved sources.

## Next implementation boundaries

1. **SRC-01 / Batch A, step 5:** Authenticated source administration with reviewed decisions, revocation and no arbitrary URLs. This register alone does not authorize approval.
2. **SRC-01 / Batch B, step 6:** Restricted HTTP fetcher with DNS/address validation, redirect revalidation, strict size/MIME/time limits and deterministic denial tests. It must remain disconnected from automatic jobs until access approval.

## Priority integration: FGIS Saturn Beekeeper Portal (2026-11-01)

The FGIS Saturn Beekeeper Portal is the first integration priority, ahead of municipal adapters. Its public, unauthenticated **human-facing** view of proposed pesticide applications is described by Rosselkhoznadzor (2025-03-26): https://base.garant.ru/411752129/ . The agency's 2026-03-27 communication lists `https://bee-saturn.ru` as the portal: https://base.garant.ru/414000975/ . A separate institutional SE-API integration guide exists at https://fgis-saturn.ru/api/seapi_%D0%B1%D1%8B%D1%81%D1%82%D1%80%D1%8B%D0%B9_%D1%81%D1%82%D0%B0%D1%80%D1%82.v2022.12.21_0900.pdf ; it does not establish the public portal's machine-readable export contract.

**Candidate-only settings:** `https://bee-saturn.ru/backend/beemaster/planapplybees`, `POST`, `subject: 55` from the earlier prototype. These identifiers and the current response schema have **not** been independently verified for production access. The configuration can be edited, versioned and used in offline request-builder tests, but is stored with `pending` permission and cannot initiate requests.

**Required before a live adapter:** inspect the official current endpoint and authentication behavior; confirm terms for automatic reads, permitted polling and downstream display; document real request/response shapes and pagination; set operator-reviewed allowlists; test TLS/DNS/redirect/size/time defenses; reconcile source status and actual field geometries. Do not treat the separately documented SE-API submission methods as a public read interface. Records must retain the original source URL and uncertainty, and historical plans must not be shown as current treatments.

## Structured treatment-plan API reference (candidate only)

The historical AgroPchela reference application (`agropchela-ai-smolensk.zip`, `server.ts`) builds an unauthenticated POST to a configurable endpoint shaped as `/backend/beemaster/planapplybees`. Its sample JSON body contains `pageNumber`, `pageSize`, `sortColumn`, `sortDirection`, and `beekeperSearchFilter.subject`; an optional `district` property is nested under the same filter. The example is **source-code evidence**, not evidence that automation, endpoint stability or redistribution rights have been approved.

The public Beekeeper Portal itself is described in the government usage materials as accessible without registration (`https://bee.fgis-saturn.ru/`); this does not independently document the legacy backend route or permit automated ingestion. The operator configures the chosen provider name, HTTPS URL and JSON parameters, all of which remain disabled for collection.

Reference response keys observed in the prototype: `content[]`, `totalElements`, `beeAcreage`, `allPatList`, and `beeAcreage.geo` (`Polygon` or `MultiPolygon`). The prototype also injected fallback polygons, locations, bee hazard classes, spectral indices, and active-state heuristics. These are **explicitly excluded** from MelliAtlas. The reference parser emits only source-supplied values and nulls. Unreviewed records are not public evidence.

## District and application-period collection research (2026-11-02)

**Evidence, not automated-access approval:** Rosselkhoznadzor's public statement describes an unauthenticated Beekeeper Portal with **district/settlement**, application-period, status, crop and hazard-class controls: https://base.garant.ru/411752129/ and https://base.garant.ru/414000975/ . The portal user guide similarly lists `region`, `district`, and `application period` as UI filters: https://admnikolskoe.ru/news/detail.php?id=1604757 . These publications verify the human-facing controls, **not** their JSON parameter names, server-side filtering semantics or automated-use license. The legacy `planapplybees` payload observed in the project supports a configurable `beekeperSearchFilter.subject` and has a candidate `district` field; exact server behavior and the mapping of `subject: 55` to Smolensk Oblast still require a controlled live check. Region code `67` in a Russian administrative identifier is not evidence that the portal's internal `subject` must also be 67.

**Captured viewport query (2026-11-03, user-supplied browser Network evidence):** `POST https://bee-saturn.ru/backend/beemaster/query` accepted a `filter` with `leftTop: {longitude, latitude}`, `rightDown: {longitude, latitude}`, `subject: "55"` (a **string**), and `query: null`, plus `pageNumber: 0`, `pageSize: 10`. The response had `totalElements: 7319`, `totalPages: 732`, `numberOfElements: 10`, `last: false` for that particular map rectangle (longitude `31.42005910644531`–`32.660140893554676`, latitude `54.496237198137145`–`55.06535182714785`). These are **observed values for one viewport**, not district coverage or stable page-size limits. Individual entries expose `id`, `planId`, `name`, `dangerBee`, `cropName`, `cadNum`, `centerX`, and `centerY`; **no `beeAcreage.geo`, plan dates, or product list** was present. Multiple parcels share one `planId`. Cadastral prefix `67:` and geographic centers are consistent with Smolensk Oblast and lend evidence to subject `55`, but do not prove its authoritative provider ID mapping. Sanitized request/response fixtures are in `apps/api/test/fixtures/saturn-map-query-*.json`; business names and cadastral values are redacted. The `/query` result MUST NOT be parsed as the polygon-bearing `/planapplybees` response or count as a completed district refresh. It cannot establish district administrative membership merely by bounding box. Whether query supports a district or application-period field, sorted/stable pagination, or a record-detail lookup remains unknown.

**No proof yet:** point/radius lookup, `updatedSince`/created-since, per-record lookup by stable plan ID, cancellation diff endpoint, accepted district/time payload JSON, response page-size guarantees, and terms for repeated automated reads or redistribution. An application-period filter does **not** select plans modified within a time interval. Do not introduce speculative request parameters or run an all-oblast fallback.

**Subscription:** The official Saturn Telegram channel announced free email subscription by region for **new, changed and canceled plans**: https://t.me/s/fgissaturn?before=181 . A published user guide describes an early-morning daily digest: https://admnikolskoe.ru/news/detail.php?id=1604757 . No authentic `.eml` sample or evidence of plan IDs, geometry or full pesticide details has been reviewed. Treat email as a prospective change signal only; do not implement mailbox ingestion from these claims alone.

**Current product decision:** The Smolensk pilot prioritizes **district-scoped, on-demand provider collection**, a **24-hour TTL from fully completed listing** keyed by actual source/config/filter identity, and a separate operator **force refresh** that does not skip external request limits. The older whole-region daily scan is superseded as a future production behavior; its existing code and old immutable evidence remain until a separately verified migration. See [S3c specification](specs/active/subspecs/source-ingestion.md#s3c--on-demand-district-collection-and-24-hour-freshness-current-priority-2026-11-02) and its [implementation plan](specs/active/subspecs/source-ingestion-implementation-plan.md#s3c--replace-whole-region-scanning-with-district-scoped-freshness-current-advisory).
