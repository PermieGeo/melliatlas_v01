# Saturn Provider Contract

**Owner:** `apps/api/src/modules/sources/providers/saturn/`. **Public composition boundary:** `index.ts`.

- Exports `SaturnViewportCollectionService`, local `createSaturnViewportClientRouter`, `createSaturnViewportOperatorRouter` and `ViewportCollectionActions`. The adapter `SaturnProvider` implements the parent module's `ViewportIndexProvider`/`DistrictDirectoryProvider` ports.
- The service exposes exact-filter `status` (database only) and explicit `fetchNext` (at most one bounded `/query` page). Explicit directory refresh fetches `/district/{regionCode}` only after PostgreSQL allowlist validation; each request receives an exact restricted-HTTPS URL policy, persistent source-wide throttle and sanitized audit.
- Inputs require a registered provider region and a directory-listed district ID within it, bounded WGS84 viewport and bounded `UpdateMap` interval. District catalog entries are named **centers**, not administrative polygons; no regional or district identity is implicitly available. Published JSON wire contracts live in `@melliatlas/contracts`.
- Stored immutable page receipts and feature/plan IDs represent a **viewport map index**, not field polygons, observed pesticide treatments, verified dates, district coverage or risk. Offline polygon/ACR ID comparison is investigatory only and does not authorize joins or publication. The offline inspector flags whether an indexed center lies inside the matching polygon's bounding rectangle and whether a separately captured ACR detail center agrees with the index within `0.000001` WGS84 degrees. Neither check authenticates spatial association; a contradiction requires investigation.
- Live access is disabled by default; explicit fetch requires reviewed source access and server enablement. Cached reads and invalid requests never contact Saturn. Loopback/origin restrictions are not production authentication.
- Other modules use `index.ts` rather than internal parsers/repos. The existing legacy treatment-feed parser remains in the parent source module. Shared geographic schema constants in `sourceProfile.ts` are currently reused by that parser; changes must preserve both validation contracts.

Feature trace: `SOURCES.DOCUMENT_HISTORY` and `SRC-R33`–`SRC-R35`. Protocol evidence and open access questions belong in the active source-ingestion specification, not in this cross-module contract.
