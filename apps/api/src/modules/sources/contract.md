# Source Ingestion Module Contract

**Owner:** `apps/api/src/modules/sources/`. **Status:** bounded manual and backend-managed region-wide provider ingestion with durable evidence and progress.

- **Responsibility:** Define source-ingestion metadata and enforce operator-reviewed destination allowlists before any future network access.
- **Public entry points:** [providerConfiguration.ts](providerConfiguration.ts) exports `ProviderConfigurationRepository` and the pure `buildProviderRequest` helper; the builder has no network access. [contracts.ts](contracts.ts) exports source, fetch policy, document, run and notice candidate schemas/types; [destinationPolicy.ts](destinationPolicy.ts) exports `evaluateSourceDestination`; [municipalSourceRegistry.ts](municipalSourceRegistry.ts) exports the internal, read-only `ApprovedSourceRegistry.getApproved(id)` (with a municipal compatibility alias) and immutable registration revision; [httpFetcher.ts](httpFetcher.ts) exports `RestrictedSourceFetcher`, `directHttpsTransport` and injectable DNS/transport boundaries.
- **Owned data:** Municipal source access policy and extraction contracts; approved municipal registrations read from `source_catalog`, whose physical schema belongs to [database infrastructure](../../db/contract.md). `source_catalog_versions` stores append-only registration snapshots. The `treatment-feed` source is fetched when explicitly requested from the local administrator UI; settings edits clear obsolete approval metadata. Manual provider sync writes immutable source documents, ingestion runs and pending spatial candidates; operator review produces verified map records. Provider candidate endpoint and request parameters are stored in `source_catalog.api_request_config`, alongside the full configured endpoint in `source_catalog.url`; operator updates use optimistic revision checks.
- **Allowed dependencies:** Zod, Node's HTTPS/DNS/TLS modules and the injected PostgreSQL pool for registry reads. URL policy itself has no network or database access.
- **Forbidden:** Arbitrary URL fetching, implicit approval of publicly visible sites, unchecked redirects, synthetic notices, or exposing operator review details through public API routes.
- **Invariants:** Fetch eligibility requires an enabled configured treatment source (or an independently approved municipal source), exact-match HTTPS DNS host and permitted path prefix. `/notices` admits `/notices/2026` but not `/notices-private`. IP literals, URL credentials, fragments and encoded traversal/separators fail closed. Structured provider polygons are validated against WGS84 coordinate bounds, closed rings and PostGIS topology; missing/invalid geometries remain `text_only`. Each verified spatial candidate requires an operator evidence note.
- **Provider boundary:** Provider settings are edited through the loopback-bound local administrator application without bearer tokens. `collectionEnabled` remains false because automatic polling is disabled; the explicit one-page fetch runs only from its separate collection action. Historical migration 005 retains its approval constraints for compatibility; treatment-fetch eligibility is now based on configured state and technical destination validation. Only an explicit manual request or a configured regional worker performs a fetch; seed presets themselves are inert.
- **Transport security:** `RestrictedSourceFetcher` requires reviewed source metadata, blocks private/special-use DNS answers, pins the validated address to a direct TLS connection with certificate validation, verifies the connected IP, revalidates each redirect and enforces body/MIME/encoding, timeout, concurrency and retry limits. No proxy or automatic decompression is used. It is invoked only from the administrator ingestion service, never from a public route or scheduler.
- **Extension:** Add a full bounded scheduler, conflict/retraction handling and alternative provider-specific parsers. `getApproved` has no HTTP route and does not trigger collection. Spatial claims require independent geometry validation. Public wire schemas belong to `packages/contracts` once endpoints exist.

- **Reference parser:** [beekeeperPlanPage.ts](beekeeperPlanPage.ts) parses one observed JSON page shape without network access, inferred values or publication authority. Different providers may require independent adapters; request configuration alone does not imply compatible responses. Optional upstream record fields may be `null` or inconsistently typed; the adapter keeps known values and marks unknown claims `null` rather than rejecting the whole page. Invalid page envelopes still fail. Validation errors in server diagnostics report only schema paths/codes, never raw records.
- **Compatibility:** Migration 004 promotes the legacy configuration to an inert `treatment-feed` source while preserving the prior row's immutable history. No source is approved by this migration.

- **Preset bootstrap:** [providerSeed.ts](providerSeed.ts) validates one `treatment` preset and seeds the existing `treatment-feed` row through a locked transaction. The default only replaces the original untouched placeholder; explicit replacement revokes prior access approval. `source_catalog.api_key` is nullable and excluded from revision snapshots and HTTP responses. The seed does not call the provider; operator edits clear the previous key. Key-at-rest protection for production is an infrastructure obligation.

- **Manual pipeline:** [treatmentIngestion.ts](treatmentIngestion.ts) owns a review-gated single-page fetch, schema-scoped session-level advisory lock (serializing workers in the same deployment schema without blocking independent test schemas), validated geometry, persisted raw JSON, run status, candidate decisions, and bounded spatial projection. `source_observation_reviews` records reviewer and evidence notes. The administrator preview endpoint may show pending validated polygons. The public notices API includes verified polygons and pending structured polygons with valid source geometry and explicit `reviewStatus`; rejected, text-only and non-structured pending observations are excluded. Operator verification remains separate from source attribution and does not imply pesticide safety. No provider access is automatically approved. The regional worker claims pages at least 65 seconds apart, persists progress in `source_catalog.source_cursor`, and can resume after restart. A configured UTC hour enables a single daily scan without region-specific hardcoded timezones. Concurrent manual and regional collection is refused.

- **Operator diagnostics:** `TreatmentIngestionService.status()` is read-only,
  returned only through local `/api/v1/operator/provider/status`.
  It shows last run/error and actual stored/pending/verified geometry counts;
  it does not trigger retrieval or include credentials/raw data.
- **Malformed geometry:** Invalid provider geometry is retained as a text-only
  candidate without fabricating a polygon or aborting unrelated valid records.

- **Manual treatment policy (migration 008):** A configured `treatment-feed` may be fetched on an explicit local administrator action without documentary permission evidence. The destination whitelist is derived from the validated persisted endpoint (no arbitrary request URL). Approved municipal registrations retain their separate review policy. Historical `access_decision` fields are not prerequisites for manual treatment fetches; individual polygon verification and SSRF/DNS/TLS limits remain mandatory. The old approval route is removed.

- **Local administration:** Server binds `127.0.0.1` and rejects non-local browser origins on `/api/v1/operator/*`. No bearer credentials are required. `PUT /api/v1/operator/provider` only saves settings. The administrator initiates a bounded `POST /api/v1/operator/provider/sync` separately and refreshes the preview. The separate probe `scripts/check-saturn-api.mjs` sends one diagnostic POST using the committed preset without writing to the database. Do not expose these routes without an independently enforced network/security boundary.

- **Regional collection:** [regionalCollection.ts](regionalCollection.ts) is the narrow orchestration entry point for read/start/pause and one claimed page at a time. [regionalScanState.ts](regionalScanState.ts) owns the validated JSON cursor state machine; progress is committed atomically with source documents and observations by `TreatmentIngestionService.syncOnePage("scan")`. Exactly one provider region is configured at a time. A scan can be partial or paused; reporting `completed` means a terminal pagination boundary was observed, not a verified immutable upstream snapshot. Source retractions and global change detection are future work.
- **Latest evidence:** Additive migration 010 introduces mutable `last_seen_at` on immutable source-document records. Re-fetching identical JSON updates only that timestamp; original raw JSON/hash and first retrieval time remain unchanged. The public viewport projection selects the most recently observed record per available `externalId` before applying publication gates, preventing duplicate stale revisions in a routine repeated scan. Missing external IDs and source-side listing reorder remain coverage limitations.

- **HTTP adapter:** [regionOperatorRoutes.ts](regionOperatorRoutes.ts) defines the narrow status/start/pause router, mounted with the existing local administrator origin boundary in `app.ts`. It performs no provider retrieval on its own and does not authorize access when mounted outside that boundary.

- **Projection boundary:** [treatmentMapProjection.ts](treatmentMapProjection.ts) owns PostGIS public/admin geometry reads and latest-version selection. `TreatmentIngestionService` delegates to it; provider HTTP, review mutation and scan status do not belong to the projection. This extracts an existing coherent responsibility from an oversized ingestion file.

- **S3c rollout boundary:** [districtCacheState.ts](districtCacheState.ts) owns 24-hour completed-coverage calculations and canonical district filter hashes; [districtCacheRepository.ts](districtCacheRepository.ts) reads district status and owns an atomic-in-evidence-transaction page update. Migration 011 persists states by source/revision/provider district/filter hash. The status endpoint is operator-only and read-only. The old `RegionalCollectionService` is no longer started by `server.ts`; no new district fetcher is active until a real district/period HTTP contract, provider ID mapping and access policy are independently verified. Refresh currently fails closed with `DISTRICT_CONTRACT_UNVERIFIED`; UI disables the action. Legacy one-page diagnostic collection remains separate and does not claim district freshness.
