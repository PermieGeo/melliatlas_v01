# Source Ingestion Module Contract

**Owner:** `apps/api/src/modules/sources/`. **Status:** reviewed, operator-triggered provider ingestion with durable evidence; no background ingestion.

- **Responsibility:** Define source-ingestion metadata and enforce operator-reviewed destination allowlists before any future network access.
- **Public entry points:** [providerConfiguration.ts](providerConfiguration.ts) exports `ProviderConfigurationRepository` and the pure `buildProviderRequest` helper; the builder has no network access. [contracts.ts](contracts.ts) exports source, fetch policy, document, run and notice candidate schemas/types; [destinationPolicy.ts](destinationPolicy.ts) exports `evaluateSourceDestination`; [municipalSourceRegistry.ts](municipalSourceRegistry.ts) exports the internal, read-only `ApprovedSourceRegistry.getApproved(id)` (with a municipal compatibility alias) and immutable registration revision; [httpFetcher.ts](httpFetcher.ts) exports `RestrictedSourceFetcher`, `directHttpsTransport` and injectable DNS/transport boundaries.
- **Owned data:** Municipal source access policy and extraction contracts; approved municipal registrations read from `source_catalog`, whose physical schema belongs to [database infrastructure](../../db/contract.md). `source_catalog_versions` stores append-only registration snapshots. The `treatment-feed` source requires explicit reviewed approval; configuration edits revoke approvals. Manual provider sync writes immutable source documents, ingestion runs and pending spatial candidates; operator review produces verified map records. Provider candidate endpoint and request parameters are stored in `source_catalog.api_request_config`, alongside the full configured endpoint in `source_catalog.url`; operator updates use optimistic revision checks.
- **Allowed dependencies:** Zod, Node's HTTPS/DNS/TLS modules and the injected PostgreSQL pool for registry reads. URL policy itself has no network or database access.
- **Forbidden:** Arbitrary URL fetching, implicit approval of publicly visible sites, unchecked redirects, synthetic notices, or exposing operator review details through public API routes.
- **Invariants:** Fetch eligibility requires an enabled source, explicit access review with evidence, exact-match HTTPS DNS host and approved path prefix. `/notices` admits `/notices/2026` but not `/notices-private`. IP literals, URL credentials, fragments and encoded traversal/separators fail closed. Structured provider polygons are validated against WGS84 coordinate bounds, closed rings and PostGIS topology; missing/invalid geometries remain `text_only`. Each verified spatial candidate requires an operator evidence note.
- **Provider boundary:** Candidate provider settings can be edited only with a server-side operator bearer token. `collectionEnabled` remains false because automatic polling is disabled; the explicit, operator-authenticated one-page fetch is separately available. Migration 005 permits `treatment` access approval only with complete operator-reviewed policy evidence. Candidate settings and seed presets do not authorize fetching.
- **Transport security:** `RestrictedSourceFetcher` requires reviewed source metadata, blocks private/special-use DNS answers, pins the validated address to a direct TLS connection with certificate validation, verifies the connected IP, revalidates each redirect and enforces body/MIME/encoding, timeout, concurrency and retry limits. No proxy or automatic decompression is used. It is invoked only from the authenticated manual ingestion service, never from a public route or scheduler.
- **Extension:** Add a full bounded scheduler, conflict/retraction handling and alternative provider-specific parsers. `getApproved` has no HTTP route and does not trigger collection. Spatial claims require independent geometry validation. Public wire schemas belong to `packages/contracts` once endpoints exist.

- **Reference parser:** [beekeeperPlanPage.ts](beekeeperPlanPage.ts) parses one observed JSON page shape without network access, inferred values or publication authority. Different providers may require independent adapters; request configuration alone does not imply compatible responses.
- **Compatibility:** Migration 004 promotes the legacy configuration to an inert `treatment-feed` source while preserving the prior row's immutable history. No source is approved by this migration.

- **Preset bootstrap:** [providerSeed.ts](providerSeed.ts) validates one `treatment` preset and seeds the existing `treatment-feed` row through a locked transaction. The default only replaces the original untouched placeholder; explicit replacement revokes prior access approval. `source_catalog.api_key` is nullable and excluded from revision snapshots and HTTP responses. The seed does not call the provider; operator edits clear the previous key. Key-at-rest protection for production is an infrastructure obligation.

- **Manual pipeline:** [treatmentIngestion.ts](treatmentIngestion.ts) owns a review-gated single-page fetch, session-level advisory lock, validated geometry, persisted raw JSON, run status, candidate decisions, and bounded spatial projection. `source_observation_reviews` records reviewer and evidence notes. An operator can inspect pending entries, but only verified polygons are exposed by the public notices API. No provider access is automatically approved.
