# Source Evidence Module Contract

**Owner:** `apps/api/src/modules/sources/`. **Provider submodule:** [Saturn](providers/saturn/contract.md).

- **Application boundary:** `TreatmentIngestionService` and source configuration/review repositories support explicit, bounded operator ingestion, immutable evidence and review decisions. Public notice projection reads stored PostGIS observations by map bounds.
- **Full treatment-page configuration:** `providerConfiguration.ts` composes bounded nested filters under the configured `regionContainer` while protecting the separately selected region. The existing `TreatmentIngestionService` imports one operator-requested `/planapplybees` page with its source-linked geometry. When Spring-style pagination metadata is present, the importer checks requested page/size, element counts, terminal-page status and total-page consistency before writing evidence or advancing the cursor. `totalPages` remains authoritative for page bounds and terminal detection even if `totalElements` is absent; only when both totals are absent does the importer fall back to `last` and then a short page. Each `beeAcreage.datePublishing` is preserved as a field-level publication timestamp in the observation attributes and projected separately from source retrieval and planned-treatment dates; absent/invalid values remain unknown. A source period whose two valid timestamps run backwards is also treated as unknown at the public/observation boundary; the full original page remains in immutable raw evidence, and another field on that page is not rejected by the database date-order constraint. This is distinct from Saturn's `/query` center-only index and does not implement completed district freshness.
- **Treatment revision ordering:** The PostGIS map projection selects the latest immutable source-document version for a field by its original `retrieved_at`, not the mutable `last_seen_at`. Re-fetching identical older JSON updates the audit recency without reviving an older plan; `retrievedAt` on the public map still reports the last sighting of the selected snapshot. This is not a verified upstream revision ordering or a district completeness guarantee.
- **Public territory navigation:** `territoryDirectory.ts` reads `territory_regions` as the independent public region catalog and uses a private `territory_region_source_codes` mapping only for saved provider district centers. Migration 017 seeds the Smolensk pilot region and registers the observed provider code for Admin without initiating source access. Public region IDs are internal, stable navigation keys; cached district IDs and centers are not official boundaries, verified completeness or filters. Additional regions and source mappings require verified evidence. Only operator routes may refresh these catalogs.
- **Shared ports:** `providerPorts.ts` defines `ViewportIndexProvider` and `DistrictDirectoryProvider`; `auditedSourceRequest.ts` coordinates source-wide request audit and throttle reservation. The generic `RestrictedSourceFetcher` enforces destination, TLS/DNS, redirect, MIME, size and time policy.
- **Published data:** source catalog, configured connection revisions, evidence documents, observation status and precision, read-only district coverage, and source-attributed map polygons. Valid structured pending polygons can be public **only with explicit unverified status**; rejected, text-only and model-pending records remain internal.
- **Isolation:** source-specific HTTP request shapes and their interpretation belong to adapters. Existing regional cursor/scan code is **not wired into server startup**; its persisted state is not proof of refreshed district coverage.
- **Non-claims:** a downloaded page, cached center, provider date field or complete viewport index is not an independently verified treatment, legal reuse right, hazard verdict or district-wide coverage.

Add a provider through its own validated adapter and documented access decision. Do not bypass server-side restricted retrieval or introduce background polling from UI reads. See [Modules](../../../../../docs/MODULES.md) for current ownership and workflows.
